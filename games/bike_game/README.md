# 바이크 칼치기 · MIDNIGHT SPLIT 3.0.0

정식 버전 `3.0.0`. 바이크가 시속 225km로 차선을 달리는 자동차들을 빠르게 추월합니다. 앞차와 간격을 유지하던 차량이 옆 차선으로 쭉 끼어들면서 위험을 만듭니다.

## 조작

- 좌우 방향키 / A, D 또는 화면의 두 조향 버튼: 이동. 부드럽게 가속하고, 손을 떼면 짧게 감속해 멈춥니다.
- Esc / P 또는 상단 Ⅱ: 일시정지 / 계속.
- R 또는 결과 화면 재도전: 같은 배치로 다시 시작. 결과 화면에서 Space도 재도전합니다.
- 처음 화면에서 새로 시작하면 새 배치를 선택합니다.

전진은 자동입니다. 가속·브레이크·부스트 조작은 없습니다. 차나 가드레일에 한 번 충돌하면 종료됩니다. 거리 제한은 없습니다. 커브에서는 바이크가 바깥으로 흐르므로, 도로 안쪽으로 조향해야 합니다. 화면의 커브와 이 힘은 같은 도로 곡률을 사용합니다.

## 교통과 끼어들기

- 4개 차선의 중앙에서 차량을 개별 생성합니다. 같은 차선의 앞뒤 간격과 차종별 속도를 사용합니다.
- 차종의 폭과 길이는 고정 규격입니다. 빈틈을 만들기 위해 차체를 늘이거나 차선을 가로로 여러 조각으로 나누어 차를 채우지 않습니다.
- 각 차선의 차량 위치와 생성 시점이 다릅니다. 빠른 차는 가까운 앞차를 따라 감속합니다.
- 끼어들기를 시작하면 목표 차선 중앙까지 계속 움직입니다. 깜빡이는 실제 이동과 함께 켜지며, 반쯤 움직였다가 멈추거나 원위치로 돌아가지 않습니다.
- 대부분 한 차선을 변경하며, 일부 경차는 두 차선을 연속 가로지릅니다. 바이크의 좌우 위치를 추적해 진로를 바꾸지 않습니다.
- 시작 전에 전체 이동 경로를 확인해 다른 차량과 겹칠 변경을 피합니다. 이미 시작한 동작의 목적지와 진행 속도는 유지합니다.

## 차종

| 차종 | 폭 × 길이 | 평상시 목표 속도 | 기본 차선 변경 시간 | 형태 |
|---|---|---|---|---|
| 경차 | 1.62 × 3.35m | 91~111km/h | 1.10~1.30초 | 짧은 해치백, 높은 뒤창, 세로 후미등 |
| 승용차 | 1.98 × 4.70m | 78~99km/h | 1.15~1.40초 | 분리된 트렁크와 보닛, 기울어진 뒤창, 낮은 지붕 |
| 버스 | 2.48 × 11.5m | 63~78km/h | 1.40~1.80초 | 긴 차체, 측면 창문 줄, 노선 표시, 지붕 공조기와 엔진 그릴 |
| 트럭 | 2.52 × 9.20m | 58~75km/h | 1.30~1.65초 | 별도 운전석, 긴 화물칸, 금속 뒷문·잠금봉, 복륜과 반사띠 |

두 차선 변경은 기본 시간의 1.55배입니다. 앞차를 따라갈 때는 표의 목표 속도보다 느려질 수 있습니다. 차체의 길이·폭·회전 방향을 충돌 판정에 반영합니다.

## 조향과 소리

- 최대 횡이동 속도를 이전 1.35에서 0.92로 낮췄습니다. 짧게 누를 때 작은 위치 조정이 가능하도록 입력 가속을 둡니다.
- 손을 뗄 때는 입력 시작보다 빠르게 감속하며, 반대로 누르면 빠르게 방향을 전환합니다. 일시정지와 재시작에서는 남은 조향 속도를 즉시 정리합니다.
- 도로는 시작 직선 이후 완만한 우커브·직선·좌커브로 이어집니다. 회전 방향을 화면에 짧게 안내합니다.
- 끼어들기는 바이크가 차량을 따라잡는 시점과 겹치도록 시작 시간을 조정했습니다. 차선 변경 도중 바뀌거나 중단되는 목적지는 없습니다.
- 지속 배기음과 바람 소리, 일반 추월 소리를 제거했습니다. 근접 추월과 충돌의 작은 일회성 효과음만 남깁니다. 상단 ‘효과음’ 버튼으로 끌 수 있습니다.

## 점수와 기록

생존은 초당 5점, 차량 한 대 추월은 30점입니다. 근접 추월은 100 × 콤보, PERFECT SPLIT은 180 × 콤보입니다. 양옆 차량을 짧은 간격으로 가깝게 추월하면 DOUBLE SPLIT 보너스 140 × 콤보가 추가됩니다. 차량 무리나 정해진 구멍을 통과하는 보상은 없습니다.

콤보는 4.5초 동안 이어지며 최대 10배입니다. 최고 점수·최장 생존 시간·소리 설정은 현재 브라우저에 저장됩니다. 정식판에서도 직전 교통 주행 버전의 기록과 소리 설정을 그대로 유지합니다. 초기 리마스터·생존 시험판의 다른 규칙으로 얻은 기록과는 분리됩니다.

## 구조와 검사

`core.mjs`는 120Hz 교통·입력·충돌 규칙, `vehicles.mjs`는 차종별 별도 도형과 입체 차체, `renderer.mjs`는 도로·주변 환경·차량 배치, `app.mjs`는 화면·입력·저장 연결입니다. `audio.mjs`는 짧은 근접 추월·충돌 효과음입니다. 이전 `racing-game.html` 주소는 현재 게임으로 연결됩니다.

```sh
python3 -m http.server 8877
node --test games/bike_game/tests/core.test.mjs games/bike_game/tests/audio.test.mjs
node games/bike_game/tests/drive-check.mjs
node games/bike_game/tests/drive-check.mjs --soak
node games/bike_game/tests/route-check.mjs
```

정적 서버에서 `/games/bike_game/`를 엽니다. 검증 범위는 `VERIFICATION_3.0.0.md`에 기록합니다. 자동 검사는 교통 배치와 이동 규칙을 확인하며 재미나 사람의 성공률을 보증하지 않습니다.

`--soak`는 64개 차량 배치를 각각 10분씩 진행하며 차량 겹침·차선 변경 완료·화면 밖 차량 정리를 검사합니다. PC 브라우저의 실제 플레이 피드백과 화면 크기별 브라우저 검사를 반영했습니다. 실제 휴대폰의 터치감·발열·장시간 성능은 별도 확인 범위입니다.

`route-check.mjs`는 12개 고정 배치의 2분 생존 경로를 탐색하고 실제 엔진으로 재생합니다. 차량의 미래 움직임을 모두 아는 탐색이므로 사람이 반응할 수 있는 난도나 모든 배치의 공정성을 보증하지는 않습니다.
