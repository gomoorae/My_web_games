# 마지막 표행 · 1.10.3

6×6에서 8×8까지 넓히는 보따리에 무기와 비급을 배치해 청하성까지 열 번의 고비를 넘는 무협 로그라이크.

## 바로 플레이

[웹에서 플레이](https://gomoorae.github.io/My_web_games/games/last-delivery/) · [게임 목록](https://gomoorae.github.io/My_web_games/)

배포 ZIP을 풀고 **Last-Delivery.html**을 브라우저에서 연다. 이 파일에 그림, 글꼴, 음악, 게임 코드가 모두 들어 있어 설치나 인터넷 연결이 필요 없다. 원본 작업 폴더에서는 빌드 후 `dist/index.html`도 직접 열 수 있다.

진행은 해당 브라우저에 자동 저장된다. 전투 중 다시 열면 일시정지 상태로 복원된다. 파일의 위치나 사용하는 브라우저를 바꾸면 다른 저장 공간으로 취급될 수 있다. 이전 3전 플레이판의 저장은 덮어쓰지 않는다.

## 1.10.3 변경 사항

- BGM으로 쓰던 ‘먼 길의 새벽’·‘청산에 이는 바람’의 원본은 약 110~116초 이후 선율이 사라지고 충격음·잡음 형태의 소리가 이어져 제외했다. 효과음 파일이 재생목록에 들어간 것이 아니라 생성 음원 내부가 무너진 문제였다.
- 새로 만든 ‘먼 길의 새벽’과 기존 ‘강호를 걷는 발걸음’·‘저녁빛 머무는 객잔’만 사용한다. 세 곡은 각각 약 3분, 합계 9분 6초다. 추가로 생성한 두 후보도 같은 후반부 문제를 발견해 제외했다. 원본과 실패한 후보는 작업 폴더에 보존한다.
- 세 곡을 무작위로 섞어 한 곡씩 끝까지 재생한다. 한 묶음 안의 중복과 묶음 경계의 연속 반복을 막고, 장면 전환에도 음악을 이어 간다. 소리 설정의 곡 수도 현재 재생목록에서 읽는다.
- 배포·단일 HTML 생성 전에 전체 구간 검토 기록과 실제 음원 해시를 대조한다. 검토되지 않은 후보, 효과음으로 분류한 파일, 검토 후 바뀐 파일은 포함할 수 없다. 검토 근거와 제외 기록은 `dist/assets/music/content-review.json`에 남긴다.

### 1.10.3 검증 범위

실제 배포용 AAC를 다시 풀어 전 구간 스펙트로그램과 15초 구간별 신호를 검사했다. 선택한 세 곡은 끝까지 변화하는 선율·배음 구조를 유지하며, 제외한 파일의 잡음 전용 후반부가 없다. 이 검사는 직접 청음이나 음색·작곡의 미적 평가를 뜻하지 않는다. 전투·저장·컷씬·효과음 재생 코드는 보존한다. 전체 자동 검사 254개를 통과했다. 실제 Chromium의 웹판·단일 HTML판에서 각각 25개 확인 항목으로 두 묶음(6곡)의 자연 종료 전환, 셔플·중복 방지, 장면 전환·일시정지·음소거 복귀, 세 음원의 해시를 확인했다. 순환 검사는 시험용 80배속이며 청음 평가를 포함하지 않는다.

## 1.10.2 변경 사항

- 첫 공격에서 효과 그림 다운로드가 뒤늦게 시작되는 문제를 막기 위해 페이지에서 원화를 미리 불러오고 디코딩한다. 준비가 끝나기 전에는 새 전투나 저장된 전투의 재개가 진행되지 않는다.
- 그림 준비가 실패하면 진행과 자원을 보존하고 다시 시도할 수 있다. 준비 중 다른 화면으로 이동한 경우 늦게 전투가 시작되지 않게 한다. 웹판과 내장 그림을 사용하는 오프라인판에 같은 준비 과정을 적용한다.
- 아래 1.10.1의 도기 방향·소모품·피격 위치·지연·줄인 모션 수정도 모두 포함한다.

### 1.10.2 검증

전체 자동 검사 250개를 통과했다. 실제 브라우저에서 효과 그림 응답을 3초 늦춘 새 전투·저장 전투 재개, 첫 다운로드 실패 후 재시도, 준비 중 화면/표행 변경을 확인했다. 그림이 준비되지 않은 동안에는 전투와 피해가 진행되지 않고, 준비 후 첫 공격부터 원화가 표시됐다. 웹판과 단일 HTML판의 실제 전투도 각 10개 확인 항목을 통과했다.

## 1.10.1 변경 사항

- 주인공 도 공격의 붉은 참격을 원화 안쪽에서만 좌우 반전했다. 이동·중심 좌표는 그대로 두고 패왕도·벽력도법·단악일도의 날이 적을 향하게 했다. 반대쪽에서 오는 적의 참격과 줄인 모션에서도 각자 올바른 방향을 유지한다.
- 독무병은 양쪽 모두 독구름, 벽력탄은 폭발로 구분한다. 소모품과 반격 이벤트에 실제 방어막 흡수량을 전달해 피해와 방어막 감소를 함께 표시한다. 피해 계산·회피·소비 횟수·난수 순서는 그대로다.
- 적 피격과 스파크·회복/방어 고리·숫자를 실제 몸통 위치에 맞췄다. 돌진 도중에도 피격 위치를 다시 읽는다.
- 찌르기 선이 지정 시간보다 먼저 보이던 현상, 바닥 가르기의 지연 누락, 독구름과 늦게 나오는 꽃잎·파편의 페이드 절단을 수정했다. 짧은 회복 오라도 사라지기 전에 페이드를 마친다.
- 줄인 모션에서 회피 글자와 가벼운 공격 예고가 즉시 사라지는 문제를 고쳤다. 원화·음악·컷씬·아이템 및 전투 수치는 유지한다.

### 1.10.1 검증

자동 검사 235개를 통과했다. 원화 방향을 직접 확인한 뒤 실제 Chromium에서 양측 5계열 무기·18종 무공·지속 피해·소모품·방어·회복 등을 95개 이벤트 조건, 4개 화면/모션 환경, 10개 시점으로 검사했다. 지연과 소멸은 별도 6개 조건으로 확인했다. 실제 게임의 도 계열 시작부터 전투까지, 모바일 화면 크기와 줄인 모션, 웹판·단일 HTML판에서도 방향과 표시를 검증했다. 저장은 테스트용으로 격리했으며 실제 휴대폰 검사는 포함하지 않는다.

## 1.10.0 변경 사항

- BGM 4곡을 매번 무작위로 섞어 각 곡을 한 번씩 끝까지 재생한다. 네 곡을 모두 들으면 다시 섞되, 직전 곡이 연달아 나오지 않게 한다. 기존 약 3분짜리 4곡, 총 12분 2초의 음원은 그대로 사용한다.
- 장면 전환·음소거·일시정지·탭 복귀에도 현재 곡과 재생 위치, 다음 곡의 순서를 유지한다. 곡 중간 반복과 장면별 음악 전환은 사용하지 않는다.
- 전용 시네마틱 그림 15장과 6개 장·60페이지로 이야기를 다시 구성했다. 폐업을 앞둔 연우의 의뢰 수락, 적운당의 구휼 물자 횡령, 증거 확보와 전달, 곽진의 체포, 실제 구호와 표국 재건까지 장소·시간·행동의 인과를 보여 준다.
- 컷씬에 이전·다음 페이지와 장 진행 표시를 제공한다. **이야기 기록**에서는 도달한 장의 요약·목표를 읽고 다시 볼 수 있다. 다시 보기는 진행·은전·수취 기록을 바꾸지 않으며, 아직 도달하지 않은 장은 잠겨 있다.
- 소연 의원과 청하상회의 공동 의뢰는 **총보수 200은전 = 선금 30 + 예치 잔금 170**이다. 시작 자금은 기존 30은전이며, 표행을 마치면 상회가 잔금 170은전을 실제로 한 번 지급한다. 구휼 물자는 주민에게 돌아가고 보수는 상회 예치금에서 지불한다.
- 결말을 건너뛰거나 저장을 다시 불러와도 잔금은 중복 지급되지 않는다. 이전 판에서 이미 완료한 저장은 보유 은전을 보존하고 **정산 기록 미상**으로 표시하며, 금액을 소급해 추가하지 않는다. 진행 중이던 이전 컷씬은 개정된 장의 첫 페이지부터 보여 주고 장비·기혈·은전·전투 진행은 보존한다.
- 이번 변경에서 전투 수치·아이템 가격·형태·전투 규칙은 바꾸지 않았다. 기존 음악과 그림 원본도 보존한다.

### 1.10.0 검증

자동 검사 218개를 통과했다. 실제 Chromium의 320·390·844·1440px 화면에서 60페이지씩 총 240페이지의 그림 디코딩·대사·버튼·가로 넘침·축소 모션·다시보기 진행 보존을 검사했다. 별도 정산 검사에서 본편 종료 시 잔금 170은전 지급, 새로고침 중복 방지, 구버전 완료 저장의 금액 보존을 확인했다. 웹판과 단일 HTML판의 실제 오디오에서도 각각 27개 검사로 8곡 셔플 종료·묶음 중복 방지·현재 곡 유지·음원 해시를 확인했다. 곡 순환 검사는 명시한 시험용 가속을 사용하며 실제 휴대폰 검사는 포함하지 않는다.

### 시네마틱 원본과 제작 기록

전용 그림은 내장 `image_gen`으로 생성했다. 로컬 작업 폴더의 원화는 `source_assets/story-v1.10.0/{id}.png`, 정확한 생성 프롬프트는 같은 폴더의 `prompts.json`, 생성·수정 기록은 `generation-records.json`에 보관한다. 배포판은 `story-*.webp` 고품질 압축본을 사용하며 원본 PNG를 덮어쓰지 않는다. 컷씬의 위치·시간·행동은 각 그림의 인물과 장면에 맞춰 연결했다.

아래 이전 버전의 변경 사항과 검증 수치는 당시의 기록이다. 현재 음악 선별은 1.10.3, 무작위 재생과 컷씬은 1.10.0 설명을 따른다.

## 1.9.0 변경 사항 · 과거 기록

- 약 3분 길이의 YuE2 연주곡 4곡을 새로 만들고, 처음부터 끝까지 정해진 순서로 재생한다. 네 번째 곡이 끝나면 첫 번째 곡으로 돌아간다.
- 준비·상점·전투·보스·결말로 화면이 바뀌어도 현재 음악과 재생 위치가 유지된다. 장면별 음악 선택과 곡 중간의 반복 구간을 제거했다.
- 기존 소리 설정과 효과음을 유지한다. 음소거·탭 이동·수동 일시정지 후에는 듣던 곡의 위치에서 이어 듣는다. 음악은 전투 배속과 관계없이 원래 속도로 재생한다.
- 새 원본은 `source_assets/audio/yue2-playlist/`에 보관한다. 이전 짧은 YuE2 원본과 합성 원본은 각각 기존 폴더에 그대로 남겨 둔다.

### 음원 제작 기록

`node scripts/generate-yue2-bgm.mjs`는 `source_assets/audio/yue2-playlist/requests/`의 180초 연주곡 요청 4개를 기존 Music 프로젝트의 공개 명령으로 순차 생성한다. 같은 요청의 검증된 원본이 있으면 다시 생성하지 않는다. 다른 원본 묶음은 `LAST_DELIVERY_MUSIC_DIR` 환경변수로 지정할 수 있으며, `journey battle`처럼 필요한 곡 이름만 인자로 전달할 수 있다. 생성 완료만으로 재생목록에 넣지 않는다.

`python3 scripts/prepare-yue2-playlist.py --track all`은 원본 해시를 대조한 뒤 전체 곡의 앞뒤 무음·음량과 짧은 시작/종료 페이드만 정리하고 AAC로 변환한다. 중간 구간 반복·길이 늘리기·곡 앞뒤 교차 편집은 하지 않는다. 결과는 `source_assets/audio/yue2-playlist/prepared/`에 저장한다. 자동 음원 측정은 사람의 청음 평가를 뜻하지 않는다.

## 1.8.1 변경 사항

- 표행·전투·최종 보스·결말 BGM 4곡을 로컬 YuE2 MLX로 생성한 음원으로 교체했다. 각각 독립된 연주곡으로 요청했으며, 기존 효과음과 소리 설정은 유지한다.
- 생성 원본은 그대로 보존하고 게임용 사본에 무음 정리·반복 경계 교차 페이드·음량 정합을 적용했다. AAC를 다시 디코딩해 클리핑과 반복 구간을 검사한다.
- 생성 요청과 원본 해시, 편집 범위, 음원 측정값을 함께 기록한다. 기존 1.8.0 합성 원본도 보존한다.

### 1.8.1 음원 기록

1.8.1의 짧은 곡 요청은 `source_assets/audio/yue2/requests/`, 완성 WAV와 생성 기록은 `source_assets/audio/yue2/`에 보존한다. 현재 실행 명령의 기본 대상은 위의 긴 재생목록이다.

`python3 scripts/prepare-yue2-bgm.py --track all`은 NumPy와 ffmpeg 또는 macOS afconvert를 사용해 게임용 사본을 `source_assets/audio/yue2/prepared/`에 만든다. 반복 경계는 자동 편집하고 측정하며, 이 검사는 사람의 청음 평가를 뜻하지 않는다. 1.8.1에서는 이렇게 만든 AAC와 반복 구간을 사용했으며 현재 재생목록은 전체 곡을 재생한다. 생성 모델 출처는 `dist/assets/music/CREDITS.txt`에 기록한다.

## 1.8.0 변경 사항

- 표행·전투·최종 보스·결말에 맞춘 보컬 없는 BGM 4곡을 추가했다. 약 70~80초 분량의 공통 주제를 현악·피리·북 계열 합성 악기로 다르게 편곡했다. 독립적으로 만든 악보와 합성 음원이며 YuE2 출력이나 실연 악기 녹음은 아니다.
- 검·도·창·암기·권의 타격음과 무공·치명타·방어·회피·회복·구매·배치·연마·승패 효과음을 새로 만들었다. 다중 장비·2배속에서 같은 효과가 과도하게 겹치지 않도록 반복 간격과 동시 재생 수를 제한했다.
- 소리 설정에서 배경음악과 효과음 음량을 각각 저장하고, 미리듣기·음소거·재생 재시도를 제공한다. 이전 음소거 설정을 유지하면서 화면에 표시한다. 브라우저 재생이 차단된 경우에도 다시 켤 수 있다.
- 음악은 전투 배속과 독립적으로 재생하며 장면 전환 시 부드럽게 바뀐다. 일시정지·탭 이동에서는 멈추고, 돌아오면 멈춘 위치에서 이어진다. 음악 파일은 필요한 장면부터 불러온다.
- 단일 HTML판에는 음악도 내장된다. `dist/index.html`을 파일로 열었을 때는 로컬 음악 스크립트를 사용한다. 첫 버튼 조작 이후 소리를 재생한다.

### 이전 합성 음원 재현

`scripts/compose-music.py`는 외부 샘플 없이 원본 악보와 합성 음원을 재현한다. NumPy가 설치된 Python에서 `python scripts/compose-music.py --track all --aac`를 실행한다. AAC 변환에는 ffmpeg 또는 macOS afconvert를 사용한다. WAV 원본과 측정 결과는 `source_assets/audio/`에 생성된다. 이 명령은 이전 합성 원본만 재현하며 현재 웹판의 YuE2 음원을 바꾸지 않는다.

## 1.1에서 유지한 개선

- 유효한 인접 연결을 맞닿은 면에 항상 표시한다. 금색 원은 무공, 청록색 마름모는 보조 효과다.

- 상시 효과와 자동 약품은 인접 연결과 구분한다.
- 당시 컷씬은 한 인물의 정확한 그림 영역과 대사창을 분리했다. 1.10.0에서는 전용 시네마틱 장면으로 교체하고 대사의 가독성을 유지한다.
- 상점·휴식·보상·전투 모두 공통 상태창에 기혈, 은전, 무기, 심법, 방어막, 활성 무공을 표시한다. 스크롤할 때도 상태창을 유지한다.
- 창고에서 각 아이템의 ↻ 버튼으로 미리 회전한다. 크기와 회전 방향을 표시하며, 다시 선택하거나 저장을 불러와도 유지한다. 자동 배치도 현재 방향을 우선한다.
- 끌어 놓을 때 잡은 위치를 유지하고 가까운 빈칸으로 맞춘다. 보따리 가장자리와 칸 사이의 여백도 허용하며, 초록색 미리보기와 실제 배치가 일치한다.
- 적의 공격은 현재 연우의 몸통 위치에 타격 효과를 표시한다. 적에서 연우로 향하는 궤적, 피격 반응, 방어막 흡수와 기혈 피해 문구를 추가했다.
- 기존 1.0 저장 형식과 호환된다.

## 플레이 방법

- 검·도·창·암기·권법 중 시작 장비를 선택한다. 보따리는 6×6으로 시작하고 상점·휴식에서 최대 8×8까지 넓힐 수 있다.
- 물건을 끌어 놓거나, 선택하고 빈칸을 클릭한다. 초록색 미리보기가 실제 놓일 자리다. **R** 또는 창고의 **↻** 버튼으로 방향을 바꾼다.
- 무기·심법·무공은 개수 제한 없이 공간만큼 장착한다. 무기는 각각 공격하고 심법은 모두 효과를 낸다. 같은 계열의 비급을 무기의 옆면에 붙이면 초식이 활성화된다. 대각선은 연결되지 않는다.
- 연결 조건에 맞는 초식은 모두 활성화되며 내공을 공유한다. 하나의 비급이 여러 무기에 닿아도 중복 시전하지 않는다.
- 같은 종류의 보조품을 여러 개 배치해도 개별 효과를 합산한다. 보조품은 설명에 적힌 인접 조건을 따른다. 전역 보조품·심법·소모품은 보따리에 넣으면 사용할 수 있다. 창고의 물건은 발동하지 않는다.
- 전투는 자동 진행한다. 1배/2배속·일시정지를 지원하고, 다른 탭으로 이동하면 정지한다.
- 전리품은 창고에 들어간다. 새 장비는 다음 전투 전에 직접 배치한다.
- 무기·비급을 선택해 은전으로 최대 3단계 연마할 수 있다. 판매도 가능하지만 마지막 무기는 팔 수 없다.
- 2·5·8전 뒤 상점, 3·6·9전 뒤 휴식. 10전의 적운당주 곽진을 쓰러뜨리면 이야기의 결말에 도달한다.
- 무림 도감에서 모든 아이템의 크기·조건·효과를 살펴볼 수 있다.
- 이야기는 이전·다음으로 넘기거나 해당 장을 건너뛸 수 있다. 이야기 기록에서 현재까지 도달한 장의 요약과 원문을 다시 본다.

## 구현된 내용

| 종류 | 수량 |
|---|---:|
| 무기 | 10 |
| 공격·방어·보조 무공 | 18 |
| 내공심법 | 6 |
| 보조품 | 16 |
| 소모품 | 10 |
| 전투 | 10 |
| 상점 / 휴식 | 각 3회 |
| 이야기 | 6개 장, 60페이지 |
| 전용 시네마틱 그림 | 15장 |
| BGM | 약 3분씩 4곡, 총 12분 2초 |

무공에는 연속 베기, 갑옷 관통, 출혈, 중독, 내공 봉쇄, 회복, 방어막, 기절, 처형, 화상 등의 서로 다른 효과가 있다. 전리품과 상점은 표행마다 달라진다. 마지막 보스는 연마된 장비와 비급 조합을 사용하며, 기혈 절반에서 결전 연출이 나온다.

전투용 전신 그림은 연우 6자세·적 8종이며, 전장 4곳·무공 효과 그림 12종·아이템 그림 60종을 새로 만들었다. 18개 무공마다 효과의 순서·궤적·타격 위치를 구분했다. 효과음은 브라우저에서 합성하고, 배경음은 YuE2로 생성해 편집한 AAC 음원을 재생한다.

## 소스 수정

ZIP에는 그림을 중복 저장하지 않기 위해 HTML 안에 넣었다. 소스를 수정하려면 먼저 `node restore-assets.mjs`를 실행하면 원본 그림·글꼴이 `dist/assets`에 복원된다. 별도 패키지 설치는 필요 없다.

- `dist/data.mjs`: 아이템·적·시작 계열·60페이지 이야기·장별 요약·의뢰 계약.
- `dist/engine.mjs`: 양측 공통 전투·능력치·보상·상점·저장 검증과 이전 저장 전환, 장 해금과 일회성 표행 정산.
- `dist/performance.mjs`, `dist/performance-ui.mjs`, `dist/performance.css`: 실제 능력치·무공별 성능·연마 비교와 결과 표시.
- `dist/grid.mjs`: 형태·회전·충돌·접촉면 계산.
- `dist/expansion.mjs`: 확장 선택·비용·크기 제한.
- `dist/enemy-loadouts.mjs`: 시드에 따른 적의 실제 보따리 구성.
- `dist/inventory-board.mjs`, `dist/inventory-board.css`: 형태 표시와 상대 보따리 열람.
- `dist/assemblies.mjs`, `dist/assembly-ui.mjs`, `dist/assembly.css`: 실제 점유와 연결을 사용하는 계열별 조립 예시와 도감 길잡이.
- `dist/app.mjs`: 화면·입력·저장·이야기 기록과 수취·정산 표시.
- `dist/audio.mjs`: 전체 곡 셔플 재생·소리 설정·일시정지 복귀·합성 효과음.
- `dist/placement.mjs`: 가까운 유효 위치 검색과 배치 보정.
- `dist/vfx.mjs`, `dist/vfx.css`: 무기·초식·적 공격별 전투 연출.
- `dist/style.css`: 반응형 화면과 그림 아틀라스 표시.
- `dist/adjacency.mjs`, `dist/inventory-ui.mjs`, `dist/inventory.css`: 실제 인접 관계·접촉면·배치 미리보기·상태창.
- `dist/cutscene.mjs`, `dist/cutscene.css`: 전용 그림·장소·시간·화자·페이지 이동을 표시하는 컷씬과 기록 다시 보기.
- `node build.mjs`: 모듈을 직접 실행 가능한 `dist/game.js`로 묶는다.
- `npm test`: 규칙과 화면 컨트롤러 검사.
- `node export.mjs`: 완전한 단일 실행 파일 `release/Last-Delivery.html`을 만든다.
- `npm start`: 개발용 정적 HTTP 서버.
- `npm install` 후 `npm run publish:web`: 이미지 압축과 소스·검사를 포함한 웹판을 `release/web`에 만든다. 첫 화면은 루트 `index.html`이며 소스는 `dist/`에 있다. 원본 작업 폴더의 PNG를 웹판에서 WebP로 변환한다.
- `node tests/balance.mjs`: 정상 자원으로 여러 시작 계열과 시드를 자동 진행한다.
- `node tests/balance.mjs 5 --multiple`: 복수 무기·심법을 쓰는 전략으로 계열당 5개 시드를 자동 진행한다.

## 검증 범위와 과거 기록

1.10.0의 최종 자동 검사·브라우저 표시·저장 호환·배포 검증은 최종 배포 작업에서 별도로 기록한다. 아래의 검사 수치와 브라우저 측정값은 각 이전 판의 기록이며, 현재 판의 최종 검사 횟수로 합산하지 않는다.

1.9.0 당시에는 순차 재생·자연 종료·일시정지 복귀·모달 독립 재생·비동기 오디오 정지 경합을 포함한 JavaScript 검사 201개와 전곡 음원 보존·AAC 인코딩을 포함한 Python 검사 6개를 통과했다. 실제 Chromium에서 개발판 HTTP·파일 직접 실행·배포 웹판·단일 HTML판의 재생과 UI 상태 35항목씩을 확인했다. HTTP에서는 첫 곡을 181.737초의 실제 길이·원래 속도로 재생해 자연 종료 후 다음 곡으로 넘어가는 것을 확인했으며, 곡 전환 공백은 약 0.115초였다. 나머지 순서와 전체 목록 순환은 검사용 가속 재생으로 별도 확인했다. 4곡의 준비 파일·내장 파일·브라우저 다운로드 해시도 일치했다. 사람의 청음·실제 휴대폰 스피커 검사는 포함하지 않는다.

1.8.1 당시에는 JavaScript 검사 194개와 음원 후처리 Python 검사 3개를 통과했다. 실제 Chromium에서 개발판 HTTP·파일 직접 실행·배포 웹판·단일 HTML판을 각각 검사했고, 각 15개 재생·음량·음소거·일시정지·장면 전환 검사와 4곡 AAC 해시 대조를 통과했다. 자동 검사와 브라우저 출력 신호 검증이며 사람의 청음·실제 휴대폰 스피커 검사는 포함하지 않는다.

1.4 당시 다중 무기·심법·무공과 인접 효과, 개별 공격 주기, 연마 전후, 배낭 능력치, 적 이펙트 방향, 저장 복원을 포함한 자동 검사 167개를 통과했다. 같은 종류 보조품의 개별 합산·사용 이펙트 출처·장비별 표시와 중복 구매·보상 획득도 포함한다. 다섯 시작 계열 모두 정상적인 전리품·상점·획득 은전으로 무기 2개와 심법 2~3개를 운용하며, UI 버튼을 조작해 10전·모든 컷씬·엔딩·저장 복원까지 이어지는 경로를 확인했다. 이전 1.2판의 별도 25회 자동 전략 실험에서는 8회 완주했고, 나머지는 8~10전에서 종료됐다. 이전 판의 간단한 자동 전략 결과이며 이번 인접 규칙의 승률이나 사람의 체감 재미를 뜻하지 않는다. 이전 판의 100회 완주율은 변경된 전투 규칙에 적용하지 않는다.

1.7에서는 계열별 조립 예시 12개의 실제 충돌·활성화·공유 보조 효과와 저장 이관을 추가 검사했다. v1.6 엔진으로 만든 저장 150개를 이관해 물건·자원·진행 보존을 확인했다. 선택하지 않은 시드 1~5를 다섯 계열의 같은 복수 장비 자동 전략으로 진행한 25회 중 18회 완주했다. 이 수치는 사람의 승률이나 최적 배치의 승률을 의미하지 않는다.

이전 1.6·1.7판은 Chromium 실제 렌더링과 터치 에뮬레이션에서 선택·창고 이동·회전·빈칸 배치·상대 보따리 확인·일시정지·배속·전투 저장 복원을 확인했다. 320·360·390·768·844·1440px 폭에서 준비·보상·상점·휴식과 8×8 보따리의 가로 넘침이 없음을 확인했다. 1.7 조립 길잡이는 320·390·768·1440px 폭에서 여섯 계열 모두 가로 넘침 없이 표시됐고, 금강호체의 홈에 청옥수를 직접 터치 배치해 무공 활성화를 확인했다. 자동 검사와 브라우저 검사에서 사용한 진행용 데이터는 검사용이며 실제 휴대폰 기기의 터치감·Safari·스피커 출력 검사는 별도다.
